# Tonia-DeskBox 视觉细节评审

> 评审时间：2026-11-23
> 评审对象：截图中同时打开的 `workdata`（展开盒）、`项目启动脚本`（折叠盒）、`文档`（面板）
> 约束：只做样式与布局层面的优化，不改功能语义与整体结构

## 0. 结论

功能与信息密度都已经到位，缺的是**一套跨窗口的结构语言**。三块卡片各自成型，但把同一个元素（标题、徽标、条目、图标按钮）放在不同窗口里时，尺寸、圆角、投影、内边距都不一样；而"半透明薄面 + 发丝边框"在彩色壁纸上撑不住层级，导致盒子看起来像壁纸的一部分而不是浮在壁纸上的物件。

三个最高杠杆的改动，做完就能拿到大部分效果：

1. **给盒子补上投影**（面板有、盒子没有），并把两个窗口的结构 token 对齐 → 解决"盒子融进壁纸"。
2. **折叠盒的信息收成一行** → 现在"6"徽标和"共 6 项"是重复信息，却占掉了卡片 40% 的高度，还把三个 16px 文件图标顶成了整卡最亮的东西。
3. **条目标签固定成两行网格 + 文字降一级** → 解决换行导致的"行距不齐"和"标题与条目同色、层级只靠字重"。

## 1. 信息层级

### A1 折叠盒的重复计数（P0）

`项目启动脚本` 卡片里同时出现：

- 标题右侧的圆形徽标 `6`
- 第二行末尾的 `共 6 项`

两者是同一个信息。更严重的是，第二行为了放这三个 20×20 的缩略图，把卡片高度撑到约 67 DIP；而这 `16px` 的文件图标在缩略尺寸下渲染成"带灰色噪点的白方块"——三块纯白成了整张卡对比度最高的元素，视觉焦点从标题跑到了缩略图。

**建议**：删掉 `共 N 项`，把三个缩略图也去掉，折叠态只保留一行 `● 名称  [6]`。卡片高度降到约 40 DIP，折叠/展开形成清晰的两级。若确实想保留"内容预览"，改成三个 4px 的类型色点（与标题同基线、gap 3），而不是 16px 图标。

代码位置：`BoxWindow.xaml` 136–160（PreviewRow / PreviewIcons / PreviewMore）

### A2 标题与条目同色（P0）

`BoxWindow.xaml` 112–114 与 `PanelWindow.xaml` 238–242：条目文字和标题都取 `Theme.Text`，层级完全靠 `SemiBold` 一档字重撑。11–12px 的小字用 SemiBold 之后，标题反而"不够重"。

**建议**：条目文字降为 `Theme.TextSecondary`（深色底 0xC7 / 浅色底 0xD6，仍是足量对比度），标题保持 `Theme.Text` + `SemiBold`。不改任何 token，只改一处 `DynamicResource`。

### A3 徽标与"映射"标签的语义冲突（P1）

`映射` 标签（`BoxWindow.xaml` 61–72）用 `FontSize=10` + `TextSecondary` + `FillStrong`，在截图里已经是全卡最弱的一段文字——读起来像"禁用项"而不是"状态标识"。同时它和徽标并排、高度接近，形成两个同等重要的胶囊。

**建议**：`FontSize 10 → 11`、`Foreground TextSecondary → Text`、`Background FillStrong → Fill`、`Padding 5,1 → 6,2`。或者更彻底：改成 12px 的图形标记（⇄），只留 tooltip 解释。

### A4 面板底部提示太弱、且下面是一片空场（P1）

`FooterHint`（`PanelWindow.xaml` 297–300）用 `TextMuted`(55% 墨色) + 11px，是全窗最弱元素；当条目只有 4 个时（截图），它孤零零挂在右下方的空白里，没有任何结构支撑。

**建议**：把底部改成**状态栏**——左侧 `共 4 项 · 2.1 MB`、右侧 `拖出放回桌面`，中间用一条 1px `Divider` 与网格隔开。空场因此变成有信息的状态区，同时与标题栏上下呼应，面板结构从"上标题 + 中间一坨 + 下面一句话"变成"头 / 身 / 脚"。

## 2. 对齐与间距

### B1 两套内边距与圆角（P0）

| 属性 | BoxWindow | PanelWindow |
|---|---|---|
| 外圆角 | `12`（第 18 行） | `14`（第 63 行） |
| 内边距 | `14,10`（第 19 行） | `12,10`（第 66 行） |
| 投影 | **无** | `Blur 18 / Depth 4 / 0.5` |

同一个产品里两块卡片并排时，2px 圆角差和 2px 左边距差会被眼睛直接读成"这不是一个东西"。

**建议**：盒子对齐面板——圆角 14、内边距 12,10；投影补上但用更低不透明度（见 C2）。

### B2 标题栏四件套的间距不均（P1）

`● workdata  8  映射`：dot→标题 8、标题→徽标 9、徽标→标签 7。三个间距是随手写的 8/9/7，且徽标是正圆胶囊（`CornerRadius=9` + `Height=18`），标签是小圆角矩形（`CornerRadius=6`）——相邻两个元素用了两种形状语言。

**建议**：间距统一 8；标签圆角 6→7（与面板图标按钮的 hover 圆角一致）；两者高度都对齐到 18。

### B3 列末留白全压在右侧（P1）

面板单元格 `88 + Margin 4×2 = 96`，`MaxWidth=400` 时内容区最多容纳 3 列（288），右侧白白多出约 88 DIP。截图里第三列的标签离右边缘明显比第一列离左边缘远。

**建议**：`MaxWidth 400 → 408`（正好 4×96 + 24），并给 `ItemsControl` 设 `HorizontalAlignment="Center"`，让不足一整列时的余量左右均分。盒子的网格同理（`74+4=78`，宽度按 78 的倍数吸附）。

### B4 图标与标签的间距两处不同（P2）

盒子 `Margin="0,4,0,0"`（第 118 行），面板 `Margin="0,6,0,0"`（第 247 行）。同一类元素、不同呼吸。

**建议**：统一 6。

## 3. 尺寸与比例

### C1 单元格没有形成"两档"（P1）

| | 盒子 | 面板 |
|---|---|---|
| 单元格 | `74×86` | `88×94` |
| 图标 | `38` | `42` |
| 字号 | `11` | `12` |
| 标签宽 | 未设（跟随 74） | `76` |

数字都在，但 74/88、38/42、11/12 之间没有比例关系，看起来像两组独立调过的值。

**建议**：明确成 **Compact / Comfortable 两档**，比例固定 0.86：Compact = `76×88` / `36` / `11`，Comfortable = `88×94` / `42` / `12`。盒子用 Compact，面板用 Comfortable。

### C2 盒子没有投影（P0，本轮最值得做）

`PanelWindow` 用"18px 透明外圈 + ShadowCaster + DropShadowEffect"做浮起感；`BoxWindow` 的 `RootBorder` 直接贴窗口边界，只有 1px 渐变边框。而边框本身在浅色底上只有 `0x40 → 0x14`（25%→8% 墨色），再叠加 20–30% 的薄面，等于没有边界——截图里 `workdata` 和壁纸几乎融成一片。

**建议**：
- 盒子引入与面板同构的 `OuterGrid Margin="18"` + `ShadowCaster`，`Opacity 0.5 → 0.30`（盒子层级低于面板，不能同强度）。
- 边框顶部从 `0x40 → 0x4D`（浅色）/ `0x59 → 0x66`（深色），保留底部 8% 让"上亮下暗"的边缘成立。
- ⚠️ 实现风险：加外圈会改变窗口尺寸与坐标，`SnapService`、`ClampIntoScreen`、`ApplySizeMode`、面板 `FollowOwner` 全部要加上 36px 的补偿。这条建议**单独提交、单独验证吸附与多屏钳制**。

### C3 折叠盒宽度没有约束（P2）

折叠态宽度由标题文字撑开，三块卡片宽度各不相同（约 290 / 355 / 374），并排时边缘参差。

**建议**：折叠盒 `MinWidth 168 / MaxWidth 260`，超长标题中间省略（首尾各留 6 字），宽度对齐 4pt 网格。

### C4 尺寸手柄像乱码（P1）

`ResizeGrip`（163–181）是 16×16 内三条 1.4px 斜线，锚在 `Margin 0,0,-2,-2`——正好压在圆角上，在薄面卡片里读起来像"≡"这种残留符号，而不是"可以拖"。

**建议**：默认隐藏，仅在 `IsMouseOver` 时淡入；改成标准的两条 45° 短斜线，内缩 4px，颜色用 `TextMuted`。

## 4. 视觉重点

### D1 accent 色用得太散（P0）

`AppearanceTheme` 给每个盒子按名字哈希出一个分类色，然后把它同时用在：**顶部分类色条、标题圆点、数字徽标、拖入边框、面板选中框、框选矩形**。

截图里最典型的是 `项目启动脚本`——整卡最饱和的颜色是顶部那条 2px 的紫色横线，而它没有任何功能含义；`文档` 面板顶部也有一条，看起来像加载进度条。

**建议**：
- 删掉 `AccentBar`（`BoxWindow.xaml` 184–188、`PanelWindow.xaml` 79–83）。注释里其实已经写了"外扩 6px 会戳出圆角边界"，说明这个装饰一直在和圆角打架。
- 徽标从 `AccentBadge`（浅色底 = accent × 0.62）改为中性 `FillStrong` + `Text`。同一张卡上就只剩**一个**彩色锚点（圆点），画面立刻安静。
- 若想保留徽标的身份色，就必须让圆点也用同一个计算值——现在圆点用原色、徽标用压暗 38% 的色，两者色相看起来都不一样（截图里一个偏粉、一个偏紫）。

### D2 面板头部三个图标权重不齐（P1）

`SearchButton / MoreButton / CloseButton`（`PanelWindow.xaml` 86–110）：按钮都是 `26×22`，但图形分别是 16×16 描边 1.5、18×16 描边 1.8、16×16 内 10px 描边 1.5。结果 `···` 明显更粗，`×` 视觉上反而更大更重，三个图标的"重量"完全不同。

**建议**：统一 16×16 画布 + 1.5 描边；按钮放大到 `28×26`；间距 4；常态 `TextMuted`(0x8C)、hover 升到 `Text`；关闭按钮 hover 背景用 12% 的 `Theme.Danger`。

## 5. 颜色 / 边框 / 阴影

### E1 文字在低透明度 + 彩色壁纸下会"化掉"（P0）

`AppearanceTheme` 只根据**盒子底色**判断深/浅墨色（`RelativeLuminance >= 0.62`），完全不知道背后是什么壁纸。截图里盒子约 20% 不透明度、浅色底、深色字，压在深蓝色壁纸上：文字算出来的合成色接近 `#2A3A66`，与卡面的对比度掉到 4.5:1 附近，11px 小字已经开始发灰。

**建议**（任选，成本递增）：
1. `MinSurfaceAlpha` 从 28 提到 60（约 24%），保证最薄的一层也还能压住壁纸；
2. 或给标题栏和条目文字加一层极淡的"可读性垫底"（标题行 `TitleBar` 已有 0x14/0x0D 的填充，可以直接复用到网格区）；
3. 或把 `IsLight` 的判定从"底色亮度"改成"底色与白/黑哪个更远"，并给浅色底强制不高于 0.85 的墨色上限。

### E2 边框几乎不可见（并入 C2）

浅色底 `0x40→0x14`，深色底 `0x59→0x14`。在 20% 薄面上，边框和背景几乎同亮度。修法：顶部提亮一档 + 依靠投影建立轮廓，不要靠加重边框（会显脏）。

### E3 面板的投影已经够用，盒子缺位（并入 C2）

`ShadowCaster` 的 `ShadowFill` 是 `alpha = 0.55 × 表面 alpha`，所以表面越透，投影越弱——这个联动是对的，盒子沿用即可。

## 6. 交互状态表现

### F1 整卡 `Cursor="Hand"` 语义错误（P1）

`RootBorder` 上挂 `Cursor="Hand"`（第 28 行），条目也是 `Hand`。结果"拖盒子"和"拖图标"光标完全一样，用户无法从光标判断当前抓的是什么。

**建议**：标题区 `SizeAll`，条目区保持 `Hand`，空白处 `Arrow`；拖拽中给卡片加 1px accent 描边作为"已抓住"的反馈。

### F2 折叠/展开没有状态指示（P1）

点标题栏会打开面板，但界面上没有任何"点这里能展开"的暗示（无 chevron、hover 时措辞也不变）。

**建议**：标题栏右侧加一个 12px 的 chevron（`⌄`），常态 35% 墨色、hover 60%，展开态旋转 180°。

### F3 缺少 press/active 态（P2）

面板图标按钮有 hover（`FillHover`）和 pressed（`Fill`），但 pressed 比 hover 更浅——按下反而变亮，方向反了。

**建议**：pressed 用比 hover 更深一档（`FillStrong`）。

### F4 文字渲染参数两窗不一致（P0，技术性但影响观感）

`PanelWindow` 有 `TextOptions.TextFormattingMode="Display"` + `UseLayoutRounding` + `SnapsToDevicePixels`（第 12–14 行），`BoxWindow` **一个都没有**。盒子可以被拖到任意像素位置，小字号在这时会比面板明显发虚。

**建议**：把这三个属性补到 `BoxWindow` 的 `<Window>` 上。

### 与原文的两处修正

1. **B1 的「12 vs 14」前提不准确**：XAML 里的 `CornerRadius="12"` 只是设计期默认值，运行期由
