## 1. 项目背景与目标

### 1.1 背景
桌面快捷方式常年在半个屏幕，找软件要瞄好几眼，截图发朋友也不好看。参考 LightBox 的思路，做一个自己的桌面收纳工具：把桌面图标"收"进一个个小盒子，桌面只留壁纸。

### 1.2 目标
- 做给自己用，功能够用、不联网、无广告、无上传。
- 单 exe（或 exe + 数据目录）绿色运行，双击即用，免安装。
- 占用小：内存 < 50MB，CPU 空闲时接近 0%。
- 桌面看起来干净：盒子本身可调成与壁纸接近的外观。

### 1.3 非目标（明确不做）
- 不做联网、不做账号、不做云同步。
- 不做桌面图标"虚拟化"（不接管 Explorer 桌面渲染），只在收纳时移动文件。
- 不做自动分类/智能识别（P2 再议）。
- 不做 Windows 10 以下的兼容承诺（Win10 能跑不保证，Win11 为第一目标）。

---

## 2. 名词定义

| 名词 | 含义 |
|---|---|
| 盒子（Box） | 桌面上的一个悬浮小控件，收起时显示名称+数量角标，点击展开图标面板 |
| 面板（Panel） | 盒子展开后的图标列表窗口 |
| 收纳 | 把桌面上的快捷方式/文件拖到盒子上，文件被移动到软件数据目录对应盒子的文件夹 |
| 取放 | 从面板把图标拖出窗口放回桌面，文件被移回桌面 |
| 数据目录 | 存放各盒子文件与配置的文件夹，默认 exe 同级 `boxes\` |

## 3. 参考产品（LightBox）功能拆解

从 PDF 中提取的 LightBox 能力，作为需求基线：

1. 一键收纳：桌面图标直接拖到盒子上，移入盒子，桌面立刻干净。
2. 分类管理：可建多个盒子，盒面显示名称和数量角标，点击展开面板。
3. 自由取放：面板内单击启动程序；按住图标拖出窗口放回桌面；盒内拖动调整顺序。
4. 自定义：盒子名称、图标样式、透明度、背景色、毛玻璃、圆角、置顶、开机自启。
5. 智能吸附：拖盒子靠近屏幕边缘自动贴边；靠近另一个盒子自动吸附并对齐（横排水平对齐、竖排垂直对齐）。
6. 交付形态：单 exe 约 3.5MB、免安装、免费、无广告、离线。

LightBox 的已知坑（本文档需规避）：
- 收纳是"移动"：文件移入 exe 同级 boxes 目录，卸载/换机前必须手动拖出备份。
- 不能以管理员运行（否则盒子挂不上桌面）、不能放 Program Files（配置写不进）。
- 首次运行 Defender 提示"未知发布者"。

## 4. 用户与使用场景

- 唯一用户：Tonia 本人（开发机 Win11，多屏，骑电动车通勤不需要考虑移动端）。
- 场景 1：装机后一次性把常用软件按"系统工具 / 办公 / 编程 / 学习"分好盒子。
- 场景 2：新装软件后随手把桌面快捷方式拖进对应盒子。
- 场景 3：临时截图前一键收起所有面板，桌面只剩壁纸和几个盒子。
- 场景 4：换电脑/重装系统，把 boxes 目录拷走即完成迁移。

## 5. 功能需求

优先级定义：P0 = MVP 必须有；P1 = 第一版就想用；P2 = 以后再说。

### FR-1 盒子管理（P0）
- FR-1.1 可创建/删除/重命名盒子；删除盒子时若盒内有文件，必须弹窗确认并提示文件去向（放回桌面 / 仅删除盒子保留文件）。
- FR-1.2 可建多个盒子（≥10 个），每个盒子独立配置。
- FR-1.3 盒面显示：名称 + 数量角标；空盒显示数量 0。
- FR-1.4 点击盒子展开面板，再点收起；同时展开的面板数量不限。
- FR-1.5 每个盒子的位置（x, y）持久化，重启后还原。

### FR-2 收纳与取放（P0，核心）
- FR-2.1 拖入：把桌面快捷方式（.lnk）、文件、文件夹拖到盒面上，文件移动到该盒子目录；支持一次拖多个。
- FR-2.2 拖出：从面板把图标拖出窗口释放到桌面，文件移动回桌面；拖到其他资源管理器窗口/文件夹时按 Windows 原生拖放语义移动/复制。
- FR-2.3 启动：面板内单击（或双击，实现期二选一并固定）启动程序/打开文件，行为与桌面快捷方式一致。
- FR-2.4 排序：盒内拖动调整顺序，顺序持久化。
- FR-2.5 图标显示：正确显示 .lnk 的真实图标（含目标程序图标），不是白框。
- FR-2.6 右键菜单：面板内图标右键可用"打开、打开所在位置、属性、从盒子移除（放回桌面）"。

### FR-3 外观自定义（P0 基础项 / P1 完整项）
- FR-3.1（P0）透明度：0%~100% 可调。
- FR-3.2（P0）背景色：颜色选择器，可取桌面壁纸近似色。
- FR-3.3（P1）圆角：可开关，圆角半径可调。
- FR-3.4（P1）毛玻璃/亚克力：Win11 原生 Acrylic，低版本回退纯色。
- FR-3.5（P1）置顶：每盒可单独置顶。
- FR-3.6（P1）盒子图标样式：内置若干主题样式可选。

### FR-4 吸附与对齐（P1）
- FR-4.1 边缘吸附：拖动盒子距屏幕边缘 < 12px 时自动贴边。
- FR-4.2 盒间吸附：靠近另一盒子时自动吸附并对齐——横排时水平对齐，竖排时垂直对齐。
- FR-4.3 吸附时可按住 Alt 临时禁用。

### FR-5 设置与系统集成（P1）
- FR-5.1 托盘图标：右键菜单含"新建盒子、显示全部、隐藏全部、开机自启开关、退出"。
- FR-5.2 开机自启：写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`（当前用户，无需管理员），可开关。
- FR-5.3 全局设置：默认外观、启动时恢复上次状态、数据目录位置。
- FR-5.4 隐藏全部/呼出快捷键（P2）。

### FR-6 数据管理（P0）
- FR-6.1 数据目录默认 `exe同目录\boxes\`，每个盒子一个子文件夹，配置为 `boxes\config.json`。
- FR-6.2 收纳=移动（与 LightBox 一致），但必须做到：删除盒子/退出程序不丢文件；提供"打开数据目录"入口方便备份。
- FR-6.3 一键备份：托盘菜单提供"导出全部盒子到 zip"（P1）。
- FR-6.4 换机迁移：拷贝 exe + boxes 目录即可，无注册表依赖（除可选的自启动项）。

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 体积 | 主程序单文件 ≤ 5MB（framework-dependent）；允许要求安装 .NET 8 Desktop Runtime，文档写明下载地址 |
| 性能 | 空闲 CPU ≈ 0%（无动画时不触发重绘）；内存 < 50MB |
| 可靠性 | 移动文件失败（目标占用/无权限）时不删除原文件，弹气泡提示并保留在原处 |
| 安全 | 完全离线；不写除自身目录与 HKCU Run 之外的系统位置 |
| 兼容 | Windows 11（22H2 及以上，含 24H2）；Win10 尽力而为 |
| 数据 | config.json 损坏时自动从 config.json.bak 恢复（每次保存先写 bak） |

## 7. Windows 11 适配要点

| 项 | 方案 |
|---|---|
| DPI/多屏 | 清单声明 PerMonitorV2；盒子跨不同缩放率的显示器拖动时尺寸不糊、位置不错乱；记录盒子所在屏幕，屏幕拔掉后自动归位到主屏 |
| 圆角 | DWM：`DwmSetWindowAttribute(DWMWA_WINDOW_CORNER_PREFERENCE = DWMWCP_ROUND)`，无边框窗显式设置 |
| 毛玻璃 | Win11 22H2+ 用 `DWMWA_SYSTEMBACKDROP_TYPE = DWMSBT_TRANSIENTWINDOW`（Acrylic）；失败回退 SetWindowCompositionAttribute 模糊，再回退纯色 |
| 深浅色 | 跟随系统 `AppsUseLightTheme` 读取，托盘菜单与设置界面适配深色 |
| 桌面挂载 | 盒子为普通置顶窗（TOPMOST 按需），不以管理员运行（与 LightBox 结论一致，避免与桌面权限不一致导致拖放失败） |
| 拖放协议 | 接收：Explorer 拖来的 `CF_HDROP` / `Shell IDList`；拖出到桌面：`DoDragDrop` 提供 `CF_HDROP` + `DROPDESCRIPTION`，实现"移动"语义图标 |
| 快捷方式图标 | `SHGetFileInfo` / `IExtractIcon` 取 .lnk 关联图标，含 jumbo（256px）尺寸 |
| 自启动 | 仅 HKCU Run；安装包不需要，绿色目录即可 |
| Defender/SmartScreen | 自用工具，签名成本高，文档写明首次运行"仍要运行"即可；不做规避 |
| 安装位置 | 文档明确：不要放 `C:\Program Files`（数据目录写入会失败），建议放 `D:\Tools\Tonia-DeskBox\` |

## 8. 技术选型

### 8.1 需求的技术本质
这个工具的核心是 4 件 Win32 层面的事：
1. 多个无边框、透明/毛玻璃、置顶的悬浮窗；
2. 与 Explorer 的双向 OLE 拖放（收 .lnk 进来、拖出去到桌面）；
3. 读取 .lnk 目标与真实图标（Shell API）；
4. 托盘、自启动等系统集成。

结论：**选型决胜点在"原生拖放 + Shell 互操作"的表现力与开发效率**，跨平台毫无必要。

### 8.2 候选对比

| 方案 | 悬浮窗/透明/毛玻璃 | OLE 拖放 | Shell 互操作 | 体积/内存 | 结论 |
|---|---|---|---|---|---|
| **C# + WPF + .NET 8 (LTS)** | 原生 AllowsTransparency + DWM Acrylic，资料最多 | 原生支持（DataObject/DoDragDrop） | P/Invoke 直调 Shell API，C# 生态成熟 | runtime 依赖模式 exe ~1-2MB，内存低 | ✅ 推荐 |
| C# + WinForms | 拖放好，但圆角/毛玻璃/动画全手写，UI 表现力差 | 好 | 好 | 小 | 备选，不推荐 |
| Avalonia | 支持，但纯 Win11 场景无收益 | 支持，拖出桌面仍要走平台层 | 需自己写 Win32 层 | 中 | 不推荐 |
| Electron | CSS 好看 | HTML5 拖放**无法与桌面 shell 互拖**，必须写原生插件 | 需原生模块 | 150MB+、内存 200MB+ | ❌ 排除 |
| Tauri | 好看 | 同样受 WebView 拖放限制，需 Rust 插件 | 需 Rust | 小 | ❌ 本机无 Rust 工具链（已验证装不上），排除 |
| C++ / WinUI3 | 最好 | 好 | 最好 | 最小 | 开发效率低，个人小工具不划算 |

### 8.3 选型决定
- 语言/框架：**C# + WPF，.NET 8 LTS**（VS 2022 开发）。
- 发布：framework-dependent 单文件（本机装 .NET 8 Desktop Runtime 即可，exe 极小）；若想要"拷到任何电脑双击能用"，再补一个 self-contained 发布配置（约 70MB，不追求 trimming）。
- 交互依赖较重的窗口层级、置顶、透明逻辑集中在 `Window` 子类，Shell 拖放与图标提取封装成独立服务类，便于单测与替换。
- 版本管理：**SVN**（沿用个人项目惯例，不用 Git）；建议结构 `trunk / branches / tags`，本地可先用 VisualSVN 或既有 SVN 服务。

## 9. 架构草案

```
Tonia-DeskBox/
├─ ToniaDeskBox.exe          # 主程序（单文件）
└─ boxes/
   ├─ config.json            # 全局配置 + 各盒子定义（位置/外观/顺序）
   ├─ config.json.bak
   ├─ 系统工具/               # 每个盒子一个子目录，收纳的文件放这里
   ├─ 办公工具/
   └─ ...
```

模块划分：
- `BoxWindow`：盒子窗体（无边框/透明/圆角/吸附/角标）
- `PanelWindow`：面板窗体（图标网格、拖出、右键菜单）
- `ShellDropService`：接收/发起 OLE 拖放（CF_HDROP、DROPDESCRIPTION）
- `ShortcutService`：.lnk 解析、图标提取（SHGetFileInfo）
- `SnapService`：边缘/盒间吸附算法
- `ConfigStore`：config.json 读写 + bak 恢复
- `TrayService`：托盘与自启动

config.json 示意：
```json
{
  "settings": { "autorun": false, "hotkey": "" },
  "boxes": [
    {
      "id": "b1",
      "name": "系统工具",
      "x": 120, "y": 640,
      "opacity": 0.85, "backColor": "#1F2A30",
      "acrylic": true, "rounded": true, "topmost": false,
      "order": ["vmware.lnk", "snipaste.lnk", "geek.lnk"]
    }
  ]
}
```

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 拖放到"桌面"语义复杂（桌面也是 ShellView） | M1 先保证拖出到"资源管理器窗口/文件夹"，桌面拖出放 M2 专项调试 |
| .lnk 图标提取个别失败 | 兜底用通用图标 + 文件名，不阻塞收纳 |
| 文件移动遇占用/同名冲突 | 冲突时取消移动并提示，绝不静默覆盖 |
| Defender 误报 | 不做壳/加壳；文档写明；必要时自签 |
| 自己改需求导致烂尾 | 严格按里程碑交付，M1 可用后再加东西 |

## 12. 验收清单（MVP）

- [ ] 双击运行，桌面出现 1 个盒子，无需管理员权限
- [ ] 从桌面拖 .lnk 到盒面 → 文件出现在 `boxes\<盒名>\`，桌面图标消失，角标 +1
- [ ] 点盒子展开面板 → 显示真实图标 → 单击启动程序
- [ ] 从面板拖图标到桌面 → 文件回到桌面
- [ ] 拖盒子到屏幕边缘自动贴边
- [ ] 退出重开 → 盒子位置、内容、外观还原
- [ ] 删除盒子有确认弹窗，文件不丢
- [ ] 任务管理器观察：空闲 CPU 0%，内存 < 50MB
